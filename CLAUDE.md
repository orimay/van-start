# CLAUDE.md

Van Start: a flashcard PWA for Dutch (never "Danish"). Nuxt 4 SPA (`ssr: false`), @vite-pwa/nuxt, Tailwind 4, Vitest.
- Offline: the service worker precaches js/css/html/png; the 21 MB SurrealDB wasm, json, images and mp3 go through runtime caches (`nuxt.config.ts`).
- Startup: `app/spa-loading-template.html` shows until the db plugin has migrated and loaded the deck.
When two rules conflict, the one written further down wins.

## Communication and process

- jj only, never git. Never interactive: `JJ_EDITOR=true`, always `-m`. No AI attribution in commits.
- Run long commands in the background. No subagents.
- Run Python with `-I`.
- Never extract or use the user's credentials from their folders. Push to the orimay repos with `~/.ssh/id_ed25519_github`.
- Sources live in `orimay/van-start` (push with `GIT_SSH_COMMAND="ssh -i ~/.ssh/id_ed25519_github"`). Commit and push each finished step; `scripts/deploy.sh` also commits and pushes the sources. Commits use `dmitrii.a.baranov@gmail.com`: the shell's `JJ_EMAIL` is the work one, so set `JJ_EMAIL` on every committing jj call.
- Ship with `scripts/ship.sh "msg"`: it snapshots the working copy into the `build` jj workspace (`../van-start-build`, made on first run with `node_modules` and `public/audio` linked in) and runs `scripts/deploy.sh` there, then moves the working copy onto the pushed `main` with its files unchanged. Editing goes on during the build; only changes made before the snapshot ship.
- Bugs follow TDD: failing test first, then the fix.
- Tests are black-box only: assert what the user sees (DOM, `data-testid`), never internals.
- Never claim audio sounds right without having heard it.
- Every decision agreed with the user and not shipped yet goes into `notes/todo.md` the moment it is agreed; tick it only once deployed.
- Work through the whole of `notes/todo.md` before stopping. Never stop on a question: the user is often away. Pick the sensible default, record it in the todo item, and keep going. Stop only when every item is shipped or truly blocked.

## Data

- `public/deck.json`: a tree of `{id, name, cards[], children[]}`. Card fields:
  - `f`: Russian translation;
  - `b`: Dutch word;
  - `tr`: transcription;
  - `n`: note;
  - `xf`/`xb`: example translation and the Dutch example;
  - `nb`/`nx`: optional extras;
  - `k`: `sentence` or `combination`, a card the learner can switch off. Set only by `python3 -I scripts/flag-kinds.py` (idempotent; its `KEEP`/`SENTENCES` lists and `SERIES` rules are the decisions, `scripts/flag_kinds_test.py` checks them). Rerun it after any deck change.
  - `p`: `noun` (it has its article) or `verb` (glossed by a Russian infinitive), set by the same `flag-kinds.py` (`part_of`). `surfaceOf` (`app/utils/surface.ts`) tints the prompt, answer and listen cards by it: an affix violet, a noun sky, a verb yellow, a letter (one-letter `b`) green, a sentence (`k: sentence`) cyan, anything else plain, in both themes, one oklch lightness and chroma for all kinds so only the hue differs, every two hues at least 40° apart, and none is red (red reads as a mistake; `surface.spec.ts`). Light: a near-white wash (`0.982 0.024`) and a clear border (`0.78 0.1`); dark: a faint wash (`0.25 0.035`) with the hue carried by a bright border (`0.6 0.1`, ≥3:1 against its card), the plain dark card a stone-600 border. Quiet text (stone-500 light, stone-400 dark) stays at 4.5:1 on every tint (`surface.spec.ts`). So one spelling as an affix, a noun or a verb looks apart (op-, de boeken, boeken).
- `public/lang/{en,es,pt,tr,ro}.json`: `cards[id] = [f, xf, tr, n?, nx?, xl?, xt?]`; an affix carries its breakdown and example transcription at 5 and 6, and `scripts/proof.py` keeps them when it rewrites a row.
- Write both compact: `ensure_ascii=False, separators=(',',':')`.
- Deck order is learning order. Groups keep the book's order. Inside a group, where its cards allow: a singular comes before its plural, a diminutive (-je) or an irregular form after its base word, and a word before every card using it, in its phrase or its example. A group's own words come first, then its sections' words in order.
- Both parts of a compound word come before it, moved there from later groups if needed: `python3 -I scripts/order-compounds.py` after any deck change. False splits (`centrum` is not cent+rum) go in its `NOT_SPLITS`.
- A prefixed word comes after its base word (laden before opladen, tekenen before betekenen, bakken before gebakken); the same script does it.
- A derived word comes after its base, and a word made of two words after both: `scripts/order-compounds.py` reads the base from each card's `от:` note.
- A compound whose part has no card gets that part as a card first (gebruiker before gebruikersnaam).
- An article comes before every noun, and every part a note names comes before the card made of it; `-je` comes before the first diminutive.
- An affix's example is the first card made with it, placed right after the affix: stem, affix, word (groeten, be-, begroeten).
- `app/utils/word-order.spec.ts` checks articles, note parts and affix examples; `app/utils/affix-examples.spec.ts` the examples' content.

## Card content (every language: ru, en, es, pt, tr, ro)

- **Goal.** A beginner learns every card from the deck alone: base always comes first, and the translation alone points to one Dutch word in one meaning. `.proof/checklist.md` is the per-card checklist; a full pass checks every card against it, then reviews each flagged card against the whole list.

- **Examples.**
  - By default an example (`xb`) uses only words from earlier cards.
  - A regular form of an earlier word counts as known: plural, present tense (droom, valt), imperative (rem!), regular participle (gekraakt, kwijtgeraakt), a split separable verb (staat stil).
  - A form that has its own card (ik was, ik ging, gestorven) counts as known only after that card.
  - Only when that is impossible, use the nearest fitting words from later cards.
  - Every example is translated into all languages.
  - Several examples go on separate lines, and the translation has the same lines, line by line, `!` kept, in every language, never left in Dutch. `app/utils/example-translations.spec.ts` checks it.
  - A `!` line is an exception and reads red on both sides, its Dutch too.
  - Examples show on the Dutch side.
- **Notes.**
  - A note is context: it tells what the card means and so what to answer. It is not an answer, not a hint, not usage trivia. No Dutch usage examples on the prompt side (`перед месяцем только эта (eind mei)` is out).
  - A note never stands `…` in for its own word: it writes the word out, inflected as the phrase needs (`in de rij staan — стоять в очереди`, `mijn horloge loopt niet`). `...` stays only for an open slot (`dit is ...`).
  - Any Dutch word hides its whole item until the answer is out (judged on the Russian twin, so every language matches). So a meaning and its Dutch example are separate items: `изготавливать или чинить; de fiets …`, `в предложении отрывается и уходит в конец; ik bel je op (я тебе звоню)`. Mentions of other words and examples show after the reveal, as links to their cards. `app/utils/note-dutch.spec.ts` checks it, and that every translated note has the Russian item count.
  - Register says it in words (`официальнее`, `обычное слово`, `короткое слово`), never by naming the other word; that word goes in its own `синоним:` item.
  - Every listed meaning has an explanation. A missing meaning gets added.
  - Every meaning is in the translation itself (`полицейский; агент`), never only in a note's "также …" item.
  - A short form names its full word as `синоним:` and back (de agent/de politieagent).
  - Close senses are told apart, e.g. eind vs einde. klok means a stationary clock.
- **Irregular forms.** An irregular form (a participle like gestorven, verdwenen, stukgegaan) gets its own card right after its base word, its meaning and a note naming the base (`причастие от sterven: is gestorven`). The base word's example uses the base form; the form card's example uses the form. Regular forms get no card.
- **Form pairs.** Singular/plural and adjective with/without -e carry identical meanings in every language (lente/lentes and herfst/herfsten once differed). A plural drops a meaning only when its note says where it went: `кружево — без мн. ч.`, or the other plural, `кости: de beenderen` (blad → bladeren for leaves, bladen for the rest); `app/utils/plural-meanings.spec.ts` checks it in all 6 languages. A singular lists every common sense of the word (blad: лист; поднос; журнал; klok: часы; колокол). Every word does, verbs too: each common sense its own `; ` item in the gloss, in all 6 languages (kunnen: мочь; быть возможным, dat kan; beginnen: начинать; начинаться; de lijn: линия; маршрут); A sense another language lists apart (de stem voice; vote) is its own item in Russian too, never run together with `, ` (de man: мужчина; муж). A word made from another keeps every sense of its base it can carry: geluk is счастье; удача, so gelukkig is счастливый; удачный; к счастью, de vriendin is подруга; девушка like de vriend, a comparative keeps each adjective sense (harder: усерднее; громче, сильнее; твёрже). `app/utils/senses.spec.ts` lists the ones once missing. Notes match too, except the usage rule: the form without -e gets the without-e rule, the -e form the -e rule (lief/lieve once shared one). An -e form drops the base's adverb meanings and its `вариант:` link (makkelijke names no gemakkelijk: no gemakkelijke card).
- **Demonstratives.** dit/dat and deze/die each name their use (near or far; het-word in the singular, or de-word and plural) and their pair; dat also its standalone and conjunction uses.
- **Adjective rule.** Every adjective with a with/without -e card pair carries the -e usage rule on both cards, before any meaning note. A note never glosses its own word's -e form as another word (`zelfstandige — самозанятый` on zelfstandig read as if the -e changed the meaning): the -e form gets its pair card, a noun made from it its own card (`de zelfstandige`, `от: zelfstandig`), which the base then links. `app/utils/form-notes.spec.ts` checks it. Every -e pair card names its base last: `форма от: groot (большой)` / `form of:` / `forma de:` / `biçimi:` / `forma lui:`, the base's sense with no inner brackets, so the base lists its -e form under «Related words»; what the word is made from (`от:`) sits on the base alone, never repeated on its -e card, so the chain reads volgen → volgend → volgende; `form-notes.spec.ts` checks it in every language. The base is the word after the article in the -e card's `!een … noun` line. An adjective whose base note carries the rule, or whose -e form the deck uses (`een flinke verkoudheid`), has its pair card; a base used with -e only as a noun, a verb or a fixed term (de jarige, de tegenwoordige tijd) is listed in the spec.
- **Variants.** Two cards of one word in different forms (eind/einde, makkelijk/gemakkelijk) name each other in the note, `вариант: …` first (also/también/também/ayrıca/variantă), in every language; a plural card puts its `мн. ч. от:` before it. When their register differs, each note says so in words (`формы взаимозаменяемы, эта разговорнее`), without naming the card's own word.
- **One word, one card.** A noun is learned with its article (de maandag, de vrijdagavond), never also as a bare card. A card with an article never hints at dropping it (no `без артикля`, `без de`): the learner would leave the article out (`article-notes.spec.ts`). When two cards merge, the kept one takes the earlier slot.
- **Style pairs.** A colloquial card and its neutral or formal counterpart (check/controleer, de opa/de grootvader, de wc/het toilet) name each other in the note, `синоним: …` (synonym/sinónimo/sinônimo/eş anlamlı) first, in every language. Every card marked colloquial, neutral or formal is checked for a counterpart in the deck.
- **Verb and phrase pairs.** One action said as a verb or as a noun with a light verb (douchen/een douche nemen, kiezen/een keuze maken, rusten/rust nemen) name each other with `синоним: …` first, then say in plain words when each is the natural pick (`обычное слово, так говорят чаще всего`; `сделать перерыв в работе или нагрузке`), plus an example, in every language. `app/utils/variants.spec.ts` lists the pairs and checks both.
- **Root families.** A derived word names its base with the base's translation, `от: …` (from/deriva de/deriva de/kökü), after any вариант/синоним or usage-rule item, in every language and every form card (plurals too). The base lists nothing back. Peers of one root, neither derived from the other, name each other both ways with `родственное: …` (related/relacionado/relacionado/akraba kelime/înrudit). Words made from one base by a suffix or none are such peers: het bezit, de bezitter and bezittelijk (all from bezitten) each name the other two in one link, `родственное: het bezit (имущество, собственность), de bezitter (владелец)`; `root-links.spec.ts` finds them from the `от:` links, skipping forms, compounds and bases whose words drifted apart (uiterlijk, de uitkering). Inside a link, meanings join with `, `, never `; `. This holds with no affix to split off too: a verb from its noun (tellen ← het tal, roken ← de rook), a noun from its verb or adjective (de groei ← groeien, het vet ← vet), an -e form, plural or superlative from its head (vele ← veel); `root-links.spec.ts` lists the pairs.
- **Verbal nouns.** A het + infinitive card meaning the process (het knutselen, het rekenen, het hoesten, het spreken) is translated as the process and carries `процесс: het + глагол (knutselen — мастерить)` (process: het + verb / proceso: het + verbo / processo: het + verbo / süreç: het + fiil) as the last note item, in every language; its verb has a card before it. The prompt itself carries the label, `рукоделие (процесс)` (`processLabel` in `app/utils/deck.ts`); the note item hides until the answer is out. Lexicalized ones keep their meaning and get no mark: het eten, het drinken, het leven, het kussen.
- **Note items.** Separate a note's items with `; `: each shows on its own line. An item opening with Dutch shows as an example, its Dutch up to ` (`, `: ` or ` — ` set in bold (`noteHead`); so a rule opens in plain words (`к отрезку времени, как dag (день), …`, `в Нидерландах café — …`), never with a Dutch word or a list of them. `note-dutch.spec.ts` checks it.
- **No hint prefixes.** No "with -e:" / "without -e:" in a rule; the card already shows it.
- **Exceptions** are highlighted in an oklch red of the same perceived lightness as the surrounding text.
- **Gender in es/pt/ro.** The `m.`/`f.`/`n.`/`pl. m.` prefix describes the translation's gender, not the Dutch word's. It is the note's first item; mixed genders join with `/` (`m./f.`). Every es/pt/ro noun card carries it; a plural card writes `pl.` plus the gender (`pl. f.`), never a bare `pl.`. Adjectives, verbs and phrases carry none; ro neuter is `n.`.
- **es is neutral Latin American.** `jullie` is `ustedes`, never vosotros; `auto`, `computadora`, `celular`, `boleto` (ticket; `billete` is a banknote), `papa`, `jugo`, `pastel`, `crema batida`, `refrigerador`, `video`, `tomar`/`agarrar`, `lentes`; `piso` is a floor, never a flat. Strongly local words (`carro`, `chévere`) stay out. Where Spain uses another word, the card's own `f` adds it second (`computadora, ordenador`, gender `f./m.`); examples use the Latin American word only.
- **es tenses mirror the Dutch form.** A perfect card (`ik heb gewerkt`) is haber + participle in `f` (`he trabajado`); `xf` stays natural Spanish. An imperfectum card takes the ru card's aspect: imperfective → imperfecto (`llovía`), perfective → indefinido. Adjectival participles (verkouden, gebroken) are left as adjectives.
- **Examples use known words.** An `nb` line, like `xb`, uses only words that have a card earlier in the deck (`de Indische keuken`, never `rijsttafel` without a card).
- **A diminutive names its base.** A `-je` card's note ends with `уменьш. от: het boek (книга)`; a diminutive compound names the base and `-je`: `от: de kaas (сыр) + de plank (доска) + -je (маленький)`. Lexicalized ones (`meisje`, `sprookje`, `toetje`, `poortje`) skip it. Same item in every language: en `diminutive of:`, es/pt `diminutivo de:`, tr `küçültme:`, ro `diminutiv de la:`.
- **Sound cards hint by meaning.** A pronunciation card's prompt names the native translation of a Dutch word with that sound, `эй (как в «два»)` for `ee`; never the Dutch word itself (it spells the answer) and never a word from a third language. Same in every language.
- **ro translation is the dictionary form.** No definite article, no `un`/`o`, no gender label in the translation: `câine`, not `câinele` or `un câine (m.)`, matching en/es/pt. Gender goes in the note. A genitive head keeps its article (`numele străzii`, `durata drumului`). So does a head before a possessive or demonstrative (`trenul acesta`, `soțul lui`), an ordinal (`clasa a doua`, `etajul întâi`), a proper name (`Ziua Regelui`) and a supine noun (`ieșitul în oraș`). Plurals take the bare plural (`ouă (pl.)`, `cartofi (pl.)`).
- **Canonical note prefixes.** Each language uses one wording per item kind, e.g. ro `de la:`, `pluralul lui:`, `a nu se confunda cu:`, `variantă:`, `sinonim:`, `diminutiv de la:`.
- **Plural cards.** The translation marks the number: ru ` (мн.)`, en and ro ` (pl.)`; es/pt/ro carry `pl.` in the gender prefix. The note names the singular first: `мн. ч. от:` / `plural of:` / `plural de:` / `çoğulu:` / `pluralul lui:` (es/pt/ro after the gender). Irregular plurals count too (-heid → -heden, aap → apen, oog → ogen); `app/composables/plurals.spec.ts` checks both. A plural card comes right after its singular. A singular card naming its plural writes `мн. de leden` / `plural: de leden` / `m. plural: de leden` (es/pt/ro, after the gender) / `çoğul: de leden`; never `pl. m. de leden`, which reads as a plural card. Every note matches the ru note's item count (`; `): the app hides an item by its ru twin, so merge extra items with `, `. Each ru `;` meaning group of a translation appears in every language, split with `;`. Grammar labels have one wording per language; pt examples use você, never tu.
- **No figures of speech.** A note says where a word is used in plain words: `сегодня почти только внутри слова de postbode`, `только внутри составных слов`, never that it "lives in" one (живёт в, lives in, vive en/em, yaşar, trăiește în). `notes.spec.ts` checks it.
- **Plain words, no grammar jargon.** Notes say what a form does, in the same wording on every card. Kept as is: `мн. ч.`, `ед. ч.`, `уменьш.`, прилагательное, существительное, глагол (a bare `мн.` in a note becomes `мн. ч.`; the ` (мн.)` translation tag stays). Replaced, ru → en/es/pt/tr/ro:
  - perfect: `прошедшее (сделал): с heb/ben`, `прошедшее (сделал) от:` / `past (did): with heb/ben` / `pasado (he hecho): con heb/ben` / `passado (fiz): com heb/ben` / `geçmiş (yaptım): heb/ben ile` / `trecut (am făcut): cu heb/ben`;
  - simple past: `прошедшее (делал, был): рассказ о прошлом` / `past (did, was): telling about the past` / `pasado (hacía, fue): para contar el pasado` / `passado (fazia, foi): para contar o passado` / `geçmiş (yapardı, idi): geçmişi anlatırken` / `trecut (făcea, a fost): povestire despre trecut`;
  - imperative: `просьба/приказ, от:` / `request/order, of` / `petición/orden, de` / `pedido/ordem, de` / `rica/emir, kökü:` / `rugăminte/ordin, de la`;
  - participle: `форма «сделанный»` / `'done' form` / `forma «hecho»` / `forma «feito»` / `'yapılmış' biçimi` / `forma «făcut»`;
  - adverb: `отвечает на «как? где?»`, only where the word does answer it (thuis: `отвечает на «где?»`); otherwise the meaning alone (echt: `в самом деле`), never a bare label;
  - particle: what it does, with an example (hoor: `в конце фразы смягчает или успокаивает; nee hoor — да нет же`), never a bare `частица`;
  - impersonal: `без того, кто делает`; passive: `с ним делают`, each likewise translated.
  - separable verb: what the part does, `op отрывается и уходит в конец` / `op splits off and goes to the end` / `op se separa y va al final` / `op se separa e vai para o final` / `op ayrılıp sona gider` / `op se desparte și merge la final`; its plain twin `не разделяется` (ik bel);
  - future: `о будущем` / `about the future` / `sobre el futuro` / `sobre o futuro` / `gelecek için` / `despre viitor`, never `будущее время`;
  - the language is `нидерландский`, never `голландский`;
  - a gloss holds no gloss of its own: `mogen (мочь, иметь разрешение)`, never `(мочь (иметь разрешение))`; inside brackets a comma, never `; ` (it splits note items). `note-dutch.spec.ts` checks every language.
- **One card per prompt.** In each language no two cards share a prompt: translation plus note. Near synonyms get a telling hint in the translation: the register or nuance (`терять (куда-то деть)` / `терять; проигрывать`), the form (`как долго (одним словом)`, `сайт (коротко)`, `мама (другое написание)`), or the article (`утюг (de-слово)`). `app/utils/duplicate-prompts.spec.ts` checks it.
- **Transcription.**
  - Per language, in that language's script.
  - Consistent across all cards, including -en forms: inside compounds, mid-word, and in comma variants (de zonen, de zoons).
  - A word-initial v is `ф`, loans too (`физи́тэ`, `фитаамии́нэ`): in the Netherlands it sounds nearly f. Between vowels it stays `в` (`зэ́йвэ(н)`), and the v sound card says it is duller than a Russian в, between в and ф. `transcriptions.spec.ts` checks the initial v.
  - Dutch u/uu is ү/үү; ю only in English loans (interview, steward). No ы, е, ё, ː (Cyrillic е leaks raw into every other language). ee is эй; ээ only before r (meer, keer). -tje is ьэ (ка́тьэ), nj is нь (спа́ньэ), -je after any other consonant is йэ (ко́пйэ, бри́фйэ). `app/composables/transcriptions.spec.ts` checks it.
  - The n of an unstressed -en, usually dropped in speech, is marked optional in every language: `лоо́пэ(н)`, `доосэ́нтэ(н)каамэр`. Never inside a root or before a d/t ending (`ви́ңкэлсэнтрүм`, `о́нбэкэндэ`), except before a tens word (`зэсэ(н)тви́нтэх`). Stress on a diphthong goes on its first letter: `э́й`, `ә́й`, `а́у`. A linking -en- said ң before k is still written `(н)` (`бу́рэ(н)каас`), only when the stem is a deck word; the ng/nk of a root stays (`брэ́ңэ(н)`, `наа́дэңкэ(н)`). A diphthong ending in i glides into the -en, which still drops: `аа́йэ(н)`, `аа́рдбәйэ(н)`. A linking -ten- keeps its (н) when a deck word follows (`э́ртэ(н)суп`), never in a root (`интэнсии́ф`). A Dutch vowel spelled as two Russian ones (eeuw as `эйу`) still links: `лэ́йувэ(н)фэрбләйф`. A word-final a is long: `аа` (`пи́тсаа`, `оо́маа`). The unstressed suffix -ig is `эх` in every form (`пра́хтэхэ`, `ә́йндэхэ(н)`, `ноо́дэхт`), never `их`. One word keeps one sound across compounds: auto is `аутоо` (`фра́хтаутоо`), garage `хаараа́жэ`, NS `эн-э́с`, machine `маашиинэ`; h stays `һ` inside a compound (`бүү́ртһөйс`, `ахтһо́ндэрт`, `фә́йлэхһәйт`), `transcriptions.spec.ts` checks each root listed in its `ROOT_SOUNDS` (huis, heid, machine, alarm, muziek, apotheek, hotel...); a new loan root that recurs goes there. -air reads `эр` (`милйоонэ́р`), ou `ау` (`ша́уэ(н)`), an unstressed open a `аа` and open o `оо` (`аала́рм`, `ли́саабон`, `һоотэ́л`, `прообэ́йрдэ`). A plural -ieën/-eeën glides with й and keeps the root's stress: `коопии́йэ(н)`, `идэ́йэ(н)`, `кни́йэ(н)`; a trema starts its own syllable, so its -en drops too (`дриийэ(н)тви́нтэх`). video is `фи́дэйоо` in every compound. An unstressed open i is a plain `и` (`солиситэ́йрэ(н)`, `дирэктөө́р`). No consonant letter is doubled, not even across a compound seam: Dutch has no long consonants (`а́фал`, `аа́нэймэ(н)`, `броо́тромэл`). Run `python3 -I scripts/mark-optional-n.py` after any transcription change.
  - Russian `tr` is the source: every other language's transcription is derived from it by `scripts/translit.py` (mark-optional-n rewrites them all). Edit ru, never another language's tr by hand. ij is spelled like ei in every language.
  - Tests: `python3 -I scripts/translit_test.py` (also checks the whole deck is derived), `python3 -I scripts/mark_optional_n_test.py`, `python3 -I scripts/sync_audio_test.py`, `python3 -I scripts/flag_kinds_test.py`.
- **Confusable pairs.** Words a learner cannot tell apart from the translation alone (aanmelden/inschrijven) carry the telling context in the translation itself (`регистрироваться (в реестре)`, `заявляться, подавать заявку`), and each note says when to use it with a short `…` example and names the other as `не путать с: …` (don't confuse with / no confundir con / não confundir com / karıştırma), in every language and every card of the word (phrases, nouns too). The hint and the Dutch example are separate note items: an item opening with `…` or `zich …` is a Dutch usage example and stays hidden until the answer is out (`DUTCH_USAGE` in `deck.ts`), as does any item naming a Dutch word; the plain hint stays shown. These labels hide like variants, in every language. Edits go through a data file `{b: {lang: (new f, note items to prepend)}}`; -e adjective forms take the base's hint and pair link. Two single words whose fronts share a plain sense (a `, ` / `; ` piece without brackets) must name each other in a reference item, and each card that names a look-alike has a plain hint item; a pair that only shares a word by accident goes in `DIFFERENT` (`app/utils/confusable-pairs.spec.ts`). A hint never holds `: ` (it would read as a label and link its words) and splits at `; ` into the same number of items in every language. Conjugated forms keep their own front and note; only forms with the base's very front take its hint.
- **A front tells its card apart on its own.** The example sentence starts hidden, so it never counts: two cards whose fronts carry the same senses, in any order (`опять, снова` / `снова, опять`), clash in that language. Mark the difference in the front itself (`опять (с досадой)`), mirrored in every language; a homonym in one language gets a meaning hint there (`paciente (enfermo)`). Affixes and forms of one another (-e forms, plurals, superlatives) are exempt. `duplicate-prompts.spec.ts` checks all 6 languages.
- **Split cards.** Merge them unless the split is justified, e.g. een paar vs het paar.
- **Realia and loanwords.**
  - A word the target language lacks gets a short explanation or a better translation, in every one of its forms (singular, plural, phrases) and in every language.
  - Format: `пепернотен (пряное печенье)`, with the note in `n`: "lit. 'pepper nuts'; for the Sinterklaas holiday, early December".
  - A short but clear explanation is enough.
  - Sinterklaas is explained too.
- **Place names.**
  - Carry a type label in every language: (город/city/ciudad/cidade/şehir), province, island, airport, museum, etc.
  - Streets get "street"; store names go in quotes.
- **Set phrases.** A phrase whose meaning is not the sum of its words (af en toe) says so as a note item, `устойчивое выражение, букв. «…»` (set phrase, literally / expresión fija, literalmente / expressão fixa, literalmente / kalıp ifade, kelimesi kelimesine), in every language; each of its words still gets its own card before it.
- **Determiners are not adjectives.** welk/welke, elk/elke, ieder take -e by gender and number only (het-word singular: none, even without een/geen); each card says so as a `!` exception item, in every language.
- **Literal first.** Of the natural translations, pick the one closest to the Dutch words and structure: hoe laat is het = `сколько времени`, een strandwandeling maken = `совершать прогулку по пляжу`, telefoneren met = `созваниваться с`. A looser idiomatic one goes in the note, if at all.
- **Plain words.** No grammar jargon a learner without a language degree would trip on. Say what it does, then a couple of examples: `действие на кого-то или что-то (лечить кого-то, готовить что-то)`, not `делает глагол переходным`; `о женщине`, not `женский род`; `маленький: -ик, -ок`, not `уменьшительное`.
- **Tense and aspect.** The translation keeps the Dutch tense: present stays present (kom je = `едешь`, not `приедешь`). A verb whose Russian aspect or voice is ambiguous says which it is, or gives both (`ходить, сходить`; `открывать` vs `открываться`).
- **Part of speech.** A noun translates as a noun (de maandagochtend = `утро понедельника`); an adverbial use goes in the note.
- **Number.** Singular and plural are visible in the translation, also in phrases (`пепернотен (мн.)`, pepernoten eten).
- **Articles.** Where de/het or its absence changes the sense (de krant lezen, in de tuin, een festival bezoeken, kerstmis vieren vs de kerstmis), the translation shows specific vs general in words (`читать газету (свою, обычную)`, `посещать фестиваль (какой-нибудь)`), and the note says why. Never name de or het in a prompt or note to say so: that hands over the article.
  - An adjective with its noun (the -e ending depends on it) says which in ru: `(конкретный)` for de/het, `(какой-нибудь)` for een, agreeing with the noun (`вкусная пицца (конкретная)`). tr says `(belirli)` or puts `bir` in; en/es/pt/ro use their own article (`the tasty pizza`, `una calle ancha`, ro the articulated form `cartea ieftină` or `o carte`).
  - A noun card always carries its article, also one Russian says without (de mazelen, het basketbal, de wifi).
  - Every article in a phrase gets a note item in ru and tr saying why it is that one, Dutch first so it hides until the answer: `een fietstocht: одно из многих или названо впервые, а уже известное — de fietstocht`. The reasons: any one or first mention (een), the known one, your own, a unique thing, a set phrase, a season or part of the day, an ordinal, a known plural, an amount (`een kopje`), an exclamation (`wat een …!`). Where one exists the item names the other form, -e ending included (`een groot huis` / `het grote huis`). These items close the Russian note; en, es, pt and ro show the article in their translation (`a bike ride`, `in the classroom`) and leave the items out, so their note lines up with the Russian one minus them (`articlesOf`, `explainsArticle` in `deck.ts`; `article-notes.spec.ts`).
  - Every phrase whose article Russian does not show says it in words: een gets `(какой-нибудь)` agreeing with the noun (`совершить велопрогулку (какую-нибудь)`), or `(какой-то)` in a sentence about a real event, `один` when ordering (`мне одно красное вино`); de/het gets `(конкретный)`, or `(свой)` for a habitual chore (`мыть окна (свои)`). tr puts `bir` in or says `(belirli)`; en/es/pt/ro carry their own article. Exempt: terms and names (de middelbare school), quantities (een beetje, een kilo), set prepositional phrases (in de zomer, op het werk), a definite topic of a sentence, and `это …` / `есть …` which already say it.
- **Parts of a word.** A word built from other words names every link of its chain, each link with its meaning, down to the root:
  - Every ancestor comes before the word built from it, each with its own card: lopen, then gelopen, then aflopen, then afgelopen.
  - Each card names its direct parent as `от:` and spells the rest of the chain after it, so the whole build shows on one card. afgelopen: `от: aflopen (заканчиваться) = af (с, от) + lopen (идти)`, `причастие`.
  - Every prefix and suffix has its own card, hyphenated (`aan-`, `be-`, `-er`, `-je`), its meanings as the translation; it comes right before the first word built on it.
    - Its note says in plain words where it goes, then shows it: separable `в предложении отрывается и уходит в конец: ik bel je op (я тебе звоню); ударение на ней`, inseparable `не отрывается от глагола, ударение не на ней: kopen (покупать) → verkopen`, word prefix `ставится перед словом: …`, suffix `ставится в конце слова: bakken (печь) → bakker`.
    - Its example (`xb`) is one short, simple word built on it (bewonen, de bakker, het katje), so the affix stands out; no long words or hard diphthongs. It is written as the word's own card, a noun with its article. `xt` is its transcription, the word card's `tr` where one exists, hand-written otherwise; `mark-optional-n.py` marks it and spells it at overlay index 6, and the affix spec checks both against the word card. `xf` glosses that word exactly as the word's own card does (`имя (личное, не фамилия)` for voornaam), since pronouncing shows only that gloss; `app/utils/affix-examples.spec.ts` checks it in every language, and that `xb` starts (prefix) or ends (suffix) with the affix. `xl` breaks the word down in every language, affix glossed as on its card, the other part with its article if a noun, `букв. «…»` only where the literal sense helps: `voor- (перед) + de naam (имя): букв. «переднее имя»`. Its parts link to their cards like a note's references (`linkBreakdown`). It splits that example word, never another (`affix-examples.spec.ts`). Overlay rows carry it at index 5. A separable prefix that is also a word is that word glued to a verb: two cards, `aan` (the word) and `aan-` (the prefix), the prefix naming the word as its origin (`от: aan (у, к)`), so the word comes first and lists the prefix among words built on it. A prefix only spelled like a word says `не путать с:` both ways (`ver-` and `ver`, далеко). A separable prefix's note shows its split on its own example verb when that is a verb: samenwonen, `wij wonen samen (мы живём вместе)`. `app/utils/prefix-words.spec.ts` checks both.
  - A derived word's `от:` names the affix card with the one meaning it uses, worded exactly as on that card, in every language: `от: aan- (при-, к, приближение) + komen (приходить)`, `от: ver- (прочь, от-, удаление) + kopen (покупать)`, `от: kopen (покупать) + -er (кто делает)`. A prefix comes first, a suffix last; a form card (plural, inflected adjective) names its lemma's affix. A prefix never reads as adding nothing: op- makes opbellen one concrete call (`op- (конкретное действие, до результата) + bellen`), and both cards say how the pair differs in use (bellen the general word, said far more often). No nested parentheses in a gloss. A gloss says what the affix does, never `меняет смысл глагола`, true of every prefix: where an old word drifted from its parts, it carries the affix's original sense, which the affix card lists (be- `исходно: вокруг, при`, so begrijpen is `be- (вокруг, при) + grijpen`), and the note adds `букв.`; `affix-examples.spec.ts` checks every language. When the word's meaning does not follow from its parts as glossed, its note says how it got there with `букв.`: betekenen `букв. «отметить знаком», как значило старое tekenen`, ontdekken `букв. «снять покров», как «раскрыть»`.
  - An affix note teaches it as a question and a rule: first `отвечает на «какой?»` (en `answers "what kind?"`, es `responde a «¿qué?»`, pt `responde a «o quê?»`, tr `«ne?» sorusuna cevap verir`, ro `răspunde la «ce?»`), then what it attaches to and examples, then `не путать с:` its look-alike both ways (-end/-ig, -lijk/-lijks). A rule item with a Dutch word puts the word first (`dank (благодарность) → dankbaar (благодарный): к существительному…`), since a Russian meaning before Dutch hides with it. Both words of an arrow carry their meaning, in every language: `sterk (сильный) → sterkte (сила)`; `note-dutch.spec.ts` checks both. An example shows only a word truly built with the affix: gedachte is ge- + denken, so it sits under neither -te nor in a -te note. Every rule holds for every word the deck builds with it: -end takes any infinitive + -d (schrijven → schrijvend); -ig mostly a noun, rarely a verb (geldig); -baar has two senses (`-емый, -имый; с этим свойством`: betaalbaar, dankbaar), and its note gives the spelling before -e (`betaalbaar → betaalbare`); -lijks is `еже-`; -te is `свойство, -ость, -ота, -ина`. A gloss that names the Russian suffix (`-ция: …`) gets an example word showing it (-tie informatie `информация`, -schap lidmaatschap `членство`, mede- medewerker `сотрудник`), and its note names the other Russian suffixes it takes (felicitatie `поздравление`); -tie is mostly -ция, -ing mostly `-ение`, each under the other's `не путать с:`; `affix-examples.spec.ts` checks the example. What an affix makes is named by its part of speech, never as a thing: `получается существительное`, ge- `из глагола делает существительное` (en `noun`, es `sustantivo`, pt `substantivo`, tr `isim`, ro `substantiv`), never `предмет`/`thing`; `notes.spec.ts` checks it.
  - An affix with several senses shows a word for each, before `от:`/`не путать с:`: `opstaan (вставать): вверх; … ; opbellen (позвонить кому-то): конкретное действие, до результата`; the item ends `: <meaning>` worded as on the front, in every language (`affix-examples.spec.ts`), so «-емый» never sits over dankbaar (благодарный).
  - An example's breakdown names real parts: de opleiding is `op- (вверх) + leiden (вести)`, never `+ de leiding (руководство)`; `leiden` has its own card.
  - Affix specs and the generator live outside the repo; the fix goes in through `scripts/proof.py apply`.
  - Every pair links: a feminine to its masculine (de genote, `женский род от: de genoot`), a compound to both parts down to the root, even through a vowel change (hij vond -> vinden) or an old part (echtgenoot: `echt (в старом смысле «брак»)`, tegenwoordig: `-woord (старое: в сторону, как англ. toward)`), a comparative, superlative or ordinal to its base (`сравнительная степень от:` / `comparative of:` / `comparativo de:` / `üstünlük derecesi:` / `comparativul lui:`; superlative `превосходная степень от:` / `superlative of:` / `superlativo de:` / `en üstünlük derecesi:` / `superlativul lui:`; a regular degree also names its affix card after the base: `сравнительная степень от: klein (маленький) + -er (-ее, -ше)`, `превосходная степень от: oud (старый) + -ste (самый)`; irregular goed and veel name only the base; the comparative -er and the agent -er name each other under `не путать с:`; ordinal `порядковое от:` / `ordinal of:` / `ordinal de:` / `sıra sayısı:` / `ordinalul lui:`). A look-alike that is not a part goes under `не путать с:` (tegenwoordig and het woord). Every overlay links the same cards as the ru note: `app/utils/links-data.spec.ts` checks it and the pairs above. A part with no card of its own (klets in kletsnat) stays unlinked; it gets a card only when the deck uses it alone. `scripts/audit-links.ts` splits every single word into cards (two words with an s/e/en seam, or an affix and a word) and lists the ones whose note reaches none of its parts within two links, and every `от:` part naming a card that does not link; `app/utils/links-audit.spec.ts` fails on any hit not in `scripts/audit-links-reviewed.json`, the hand-checked false splits (kamer is not kam + -er), and on any entry there the audit no longer finds. A part spelled like two cards (leven, het leven) counts as linked through either. A new hit gets its link, or, when the split is false, its line in that file. Every single word that looks affixed (ge-, be-, ver-, ont-, her-, -ing, -heid, -lijk, -ig, -baar, -loos, -schap, -nis, -ling, -achtig, -lijks) names its parts in every language, opaque ones too: a part with a card is linked, a root without one is named beside it (`de aard — нрав, характер`, an old root `vro — старое «радостный»`), a participle of a verb without a card says `форма «сделанный» от: wennen (привыкать)`. So does every single word that is any deck affix plus another deck word, spelling changes undone (spannend = spannen + -end, de opvang = op- + vangen, langzamer = langzaam + -er). Only a word that merely looks affixed (de koning, de kamer) or whose affix is fossil (geloven, gezond) stays unsplit, listed in `app/utils/affix-split.spec.ts`.
  - A label is any text before `: ` that does not end on a gloss: `opbellen (позвонить кому-то): …` is an example, not a label. Only an origin label (`от:` and its translations, the diminutive ones) feeds «Derived words»; every other label feeds «Related words».
  - A new part named in a note moves the deck: `python3 -I scripts/order-compounds.py`. When an affix moves earlier, its example and the example's stem move with it (stem, affix, example), so the example stays the first card made with it and keeps its audio.
  - Compounds split the same way, every part a card: het liedwoord = lied + woord, de paddenstoel = pad (жаба) + stoel (стул), bepaald = be- + palen (ставить столбы, ограничивать). A part whose meaning is lost says so (`букв. «жабий стул»`), and a truly opaque word says `происхождение неясно`, never silence.
  - A phrase (any multi-word card that is not a sentence, a name or a form) names its words' cards the same way, each with the sense it uses: een douche nemen `от: de douche (душ) + nemen (брать)`, ten slotte `от: het slot (конец)`. A sub-phrase with its own card is one part (`laat maar zitten` names laten). A collocation with a light verb (nemen, doen, maken, zetten, voeren, stellen, hebben, geven, leggen, krijgen) says why that verb in every language, against its near-synonyms: `почему nemen: душ, ванну, отдых «берут», как англ. take a shower`. `app/utils/phrase-parts.spec.ts` checks every phrase; one whose word has no card yet sits in its `NO_PART_CARD`, and leaves it once linked.
  - Every word of a multi-word card is accounted for in its `от:`, in every language and in the same order: de voltooid tegenwoordige tijd names voltooid, tegenwoordig and de tijd. Articles and pronouns aside, a word counts when it is a named part, a form of one (hij hoort bij → horen bij), or a compound of two named pieces. A word with no card is glossed after the parts, `voltooid — «завершённый»` (en `"…"`, ro `voltooid = «…»`). `phrase-parts.spec.ts` (`a multi-word card`) checks ru and that every overlay names the same parts.
  - A verb form with its own card (hij neemt, ik pak, neem) names its infinitive with `форма от: nemen (брать)` / `form of:` / `forma de:` / `biçimi:` / `forma lui:`, or the perfect/imperative label for those forms; `verb-forms.ts` (`formsOf`) spells every form of a verb, and `verb-form-links.spec.ts` checks every form card names its verb in every language and no card is called a form of a verb it is not one of; a card only spelled like a form (het, laat) sits in its `NOT_A_FORM`.
  - A card out of place moves earlier, to just before the first card that cannot come before it; the later card never moves back.
  - Inflected forms join the chain where they are their own card (gelopen); regular ones do not (see Irregular forms).
- **One sense per example.** An example of a card with several senses shows one of them, and its translation names no other sense of the card through another word: het pak `Hij draagt een nieuw pak.`, never `Doe het pak in een tasje.` / `Положи костюм в пакет.`, where пакет is the tasje. `app/utils/example-senses.spec.ts` checks all 6 languages; the word said twice or a ` / ` translation shows two on purpose (dag).
- **Every meaning.** A card lists every common meaning, the one its examples use first (stranden, bladeren, het lid, boodschappen doen). Check a suggested meaning in a dictionary before adding it.
- **Accuracy.** No narrowing beyond the word: warm = `тёплый`, chocolademelk is not only hot.
- **Close pairs.** Near-synonyms and look-alikes (zaterdagmorgen/zaterdagochtend, mailen/e-mailen, naar huis/thuis) follow the confusable-pairs rule above.
- **Spelling and audio.** Spelling follows the official rules (half één); the audio matches the spelling.
- **Worked cases** (was -> should be), the pattern to copy for any similar card:
  - Kom je met de fiets? `Ты приедешь на велосипеде?` -> `Ты приезжаешь на велосипеде?` (present stays present; kommen = приходить / приезжать, never ехать, which is gaan / rijden). A note may add that Dutch present often means the near future.
  - Hoe laat is het? `Который час?` -> `Сколько времени?` (literal first).
  - een strandwandeling maken in de storm `гулять по пляжу в шторм` -> `совершать прогулку по пляжу в шторм`.
  - de maandagochtend `в понедельник утром` -> `утро понедельника`; note: `op maandagochtend — в понедельник утром`.
  - openen `открывать` -> `открывать (что-то); открываться`, if both uses exist; else name the one.
  - een festival bezoeken `сходить на фестиваль` -> `посещать фестиваль (какой-нибудь)`; de krant lezen -> `читать газету (свою, обычную)`; note says why de / een / none.
  - kerstmis vieren vs de kerstmis: both cards say a holiday name goes without an article in phrases like vieren.
  - de pepernoten `пепернотен` -> `пепернотен (мн.)`; de pepernoot -> `пепернот (одна штука)`.
  - warme chocolademelk `горячий шоколад` -> `тёплое какао с молоком`; de chocolademelk -> `шоколадное молоко` (hot or cold).
  - afgelopen `законченный` -> `прошедший, закончившийся`; note `от: aflopen (заканчиваться) = af + lopen (идти)`, `причастие`; aflopen, lopen and gelopen come before it.
  - om half een -> om half één (spelling and audio).

## Games and UX

- **Icons.** Outline SVG on a 24 grid, `stroke="currentColor"`, `stroke-width="1.5"`, round caps and joins, one component each (`ContextIcon`, `LaterIcon`). No emoji as icons.
- **Games.** Five games: reading, speaking, writing, listening/dictation, pronunciation. Each can be turned off in settings.
- **Dictation hears, it does not see.** A spelling that sounds the same as the answer (`soundsLike`: ij/ei, ou/au, final d/dt/t) counts as right, with "Sounds the same, spelled X", only when every typed word the answer lacks is a word of a learned card (`spelledInKnownWords`, `TypeGame`'s `learnedWords`): het hard for het hart once hard is learned. A made-up spelling (allebij) is a miss; an unlearned deck word goes to the mix-up flow.
  - All are on by default. At least one always stays on.
  - Recognizing (choice): Next shows and works only after a wrong pick; hidden it is disabled.
  - Review runs in the chosen game; if that game is off, the first enabled one is used.
- **Learning.**
  - New words come in deck order.
  - Optionally a group opens with pronouncing in place of the intro; pronouncing is then not played again later. Whatever introduces the words (intro, or pronouncing in its place) keeps deck order; every other game shuffles.
  - Each section keeps its own spot to continue from; a topped-up group's spot holds its following-section words too.
  - A short last group is topped up only to the next multiple of five, never past the group size; a group already at a multiple of five is not topped up. Top-up takes the following words when set so, and with none left the most missed learned words (most lapses, then hardest).
  - Progress is per card and per game, shared by every group and kept after a card is learned.
  - Status is measured against the games on now, intro or pronouncing-first included: through all of them is learned, through none is new (whatever was passed in games now off), through some is started. A card learned before games were tracked counts as learned.
  - A section with started words offers to continue before anything else, top-up included, listing the passed games with their word counts. Continuing goes through the section in deck order; a card in a group, topped-up ones included, skips the games it passed.
  - Starting over first lists the passed games with their word counts and warns that this progress is dropped; it drops it for the section's started words only.
  - A group goes game by game, from the earliest one any of its cards has not passed; each game takes only those cards, shuffled (the intro keeps deck order).
  - The same card never shows twice in a row.
  - A mistake climbs the ladder while new cards are left to space it; what they cannot space moves to the next group.
  - Shuffling: a card's chance grows with time since it was last shown or touched, counting 5:5 / 1:5 rounds.
- **Cards in games.**
  - In every mode (1:1, 5:5, 1:5, recall, typing) cards have notes and the same size.
  - Dividers do not jump.
  - A card too long for its half scrolls its transcription, notes, example and breakdown (`prompt-scroll` / `answer-scroll`); only the word stays in view. The word keeps clear of the corner badge and the `?` button (`px-7`). The half centres with `justify-center-safe`: plain `justify-center` cut the top off a card taller than its half.
  - `ScrollBox` draws its own scroll thumb whenever the content overflows: a phone's own scrollbar fades out after each swipe, so the reader would lose the hint that more is below The thumb runs on a drawn track, so its position reads as a share of the whole.
  - A word opening with a hyphen (`-er`, `(-ing)`) never wraps away from its hyphen: a break after it reads as a dash. Prompts, answers, options, tiles and notes render text through `KeepAffixes`.
  - Spacing follows focus-assistant's ladder (4/8/12/16 px): parts of one piece sit closest, separate blocks further apart. The word and its transcription 4px; the context box and the notes 12px apart (`gap-3`); note lines of one group (`RANK`) 4px, a new group 8px.
  - Under the word come its breakdown (where the example comes from) and then the example, in a shaded box, apart from the notes below it: a bulleted, left-aligned list when there are several items, so a centred wall of lines never forms.
  - Note items are styled by kind (`noteKind` in `app/utils/deck.ts`, drawn by `NoteList.vue`): a rule is a plain bullet; an example hangs under a left rule in italics, its Dutch in strong type; a `label:` item (`не путать с:`) and the origin (`… от:`) open with a small uppercase label, the origin set off by a line above. A translation takes the kinds of its ru twin when the items line up; `nx` lines are examples. No two `nx` lines of a card read the same in any language: ru, having no articles, marks `het`/`de` with `(конкретный)` and `een`/`geen` with `(абстрактный)`, in the noun's gender (`example-lines.spec.ts`). Rules and labels come first, then the origin, then the examples. A word opening with a hyphen (`(-ing:`) never breaks after the hyphen (`NoteText.vue`).
- An affix named in another card carries that affix card's gloss, the whole of it or one piece (a `; ` sense, the part before `: `, or a part split at `, ` / `: `): the affix card is the one source, `affix-examples.spec.ts` checks every language. A gloss says what the affix makes plainly enough to tell it from a near one: -end `-ющий: делающий что-то` (an action, «что делающий?») vs -ig `-ный, -истый: какой, с тем, от чего образован` (a quality, «какой?»). No two affixes share a gloss in any language (`affix-examples.spec.ts`): affixes that make the same thing name what picks one, after `: `, and each names the other under `не путать с:`. -es `о женщине: после -er, -aar` vs -in `о женщине: не после -er, -aar`; -te `свойство, -ость, -ота, -ина: к некоторым коротким прилагательным` vs -heid `свойство, -ость: к любому прилагательному`. A gloss naming only what the affix means also fails when another affix means the same: -tie `-ция: в заимствованных словах` vs -ing `-ение: действие или его результат`; -aar `кто делает: к основе на -el, -er, -en` vs -er `кто делает; что делает, прибор; житель`. The spec fails when every sense of one gloss is a sense of another.
- A derived word whose meaning does not follow plainly from its parts gets a literal bridge after its origin, in every language: `букв. «от-сказать», как «отказать»: сказать, что не придёшь` (afzeggen). One form per language, `app/composables/notes.spec.ts` checks it: ru `букв. «…»`, en `literally "…"`, es/pt `literalmente "…"`, tr `kelimesi kelimesine "…"`, ro `literal „…”`.
  - A closed card keeps its example back (it would prompt the word): `Show context` stands in its place, and a tap anywhere on the card shows it, at no cost; the open card shows it as usual.
  - Text wraps balanced (`text-wrap: balance` on body): no last word left alone on its line.
  - 1:5 shows only examples from the current set.
- **Navigation.**
  - The user can go back to the previous card. Back restores the card's last state.
  - No swipes: cards move only by buttons, which show what they do.
  - Before the meaning is out, a Dutch-side prompt hides its picture (it would give the meaning away) but keeps its place, so nothing jumps.
  - Before the answer is out, every note item that hints at the Dutch word stays hidden in place: its forms, `вариант:`/`синоним:`/`родственное:`/`от:` items, and any Russian item with Dutch in it except the allowed de, het, een, geen and -e. A translated item hides when its Russian twin does. Usage rules stay shown. Pronouncing (and meeting a word through it) hides nothing: the Dutch is already on screen.
  - Buttons never vanish mid-card: one not usable yet is disabled, so nothing jumps.
  - "left" counts cards of the game not passed yet; a retried card counts once.
  - Review has no limit: it asks every card due now.
  - Review gaps follow 2-7-30: a learned word is due on day 2, each right answer moves it to 7, then 30, then doubles the gap; a miss starts over at 2, and putting it right in the same session keeps 2. Each gap counts from the last answer, per word and per game. A right answer before the word is due credits only the ladder gap its elapsed days cover (day 3 of a 2-7 step counts as the 2, so next is 7 from now); under 2 days changes nothing. Once the due time has come the whole step counts.
  - In a session, learning and review alike, every card game (listening included) follows the ladder below: a miss or a guess comes back after exactly 4 shown cards, each right answer moves it a rung up, past the top it is passed. A right answer with no other card left passes it.
  - A guess comes back like a miss but is graded neither way (no FSRS grade, no score, no error, not toward accuracy; stepping back gives the card a fresh grade): recall shows Guessed beside Example only after Reveal (before it Card and Example take the whole row), Forgot beside Remembered; typing offers Guessed in place of No idea once the answer is right; choice has a Guessing toggle pressed before the pick.
  - Every group, Continue included, is filled with the words not learned in all games on, in deck order, up to the group size; whether a word was seen before never changes its place. Then each game but the intro (or pronouncing in its place) shuffles by the seed and expected frequency (past mistakes), and runs that order skipping the words that passed it. Continue restores the saved spot only when it holds the very group built now (same ids, same order); a stale spot gives way to the fresh group from its first game. Only an update reload restores the exact spot unconditionally.
  - The offer to continue shows a bar per game on: words of the group to continue that passed it, out of the group.
  - A short group is topped up as set in Settings: words that gave trouble (default) or the next group's words. No question.
  - Pronouncing plays with two buttons: Card and Example, or Compare and Example once a recording exists.
  - Mixed up (`MixUpSheet.vue`): after Reveal, every recall offers Mixed up as `≈` in the answer card's top-left corner, mirroring `?`; the button row keeps three buttons so Card never wraps. It opens a search over the whole deck by Dutch (past the article, compounds inside) or by a meaning's start in the native language, closest first: where the query starts (the start of the word first, then further in), then how much more the text holds, Dutch before meaning among equals, so `terug` lists `terug`, `terug-`, then `terugweg`, `terugkomen`, then `de weg terug` (`matching` in `utils/mix-up.ts`); before anything is typed it suggests the single words built on this one or it on theirs (a phrase holding the word is not one), then look-alikes. The card itself and the ones already linked are left out. Picking one links both cards (`confusions` doc, `app/utils/confusions.ts`, both ways), counts the card as a miss and the picked one as missed too (graded wrong; review reschedules it only when it is learned), and brings the picked one back like a miss when the session holds it. Back takes both answers back; the link stays.
  - A mix-up never moves the card on: it stays with the `≈` pill naming the picked words and a hint that both (or all, for several words) come back as missed; Forgot (or Next) moves on. Remembered and Guessed are off only while a mix-up picked on this very step stands; one linked earlier, or picked and taken back, leaves them on. The picker keeps a picked card in place, ticked, and a second tap unpicks it. The step's picks survive a resume (`CardState.mixed`, `linked`).
  - Only once the answer shows (Reveal; in typing, Reveal answer, never a retry), the words linked earlier and not picked on this step are listed in a row of their own above the answer word, after a ≈, newest first (`MixedBefore.vue` in Answer's `#above` slot; in the corner they ran over the word; linking a pair again moves it to the end of `confusions`). Shown sooner, a retry would steer clear of the known-wrong word and the other card would never get its miss. In a step the picker lists them first under "Mixed up before", unticked: a tap picks one again, both count as missed again and the link stays; taking it back keeps the link too. Only a link this step made is undone on taking it back.
  - Two forms mixed up mix up their bases too: hij pakt with hij neemt links pakken and nemen (`withBases` in `utils/confusions.ts`; a form's base is the card its `форма от:` / `прошедшее (…) от:` / `просьба/приказ, от:` / `мн. ч. от:` item names, `basesOf` in `utils/links.ts`). The base link is derived on every read, never stored, so it holds as long as the forms' link does and goes with it. Undoing it on the bases undoes the forms' link that carries it; a base link made on its own stays when the forms' link comes off.
  - Any miss (recall, typing, choice; not a guess, not match) counts every card directly linked to it as missed too and brings those back like a picked mix-up, so a pair once mixed up is drilled together; links of links are not followed (`missLinked` in `Session.vue`).
  - Typing: a wrong answer that is another card's answer (same direction) is that mix-up, linked on its own (`typedAs` in `utils/mix-up.ts`). A form written exactly so, symbols, hints, case and marks counted, is chosen on purpose: `terug-` is only `terug-`, `één` only `één`, `een (one)` only `een (one)`. A plain form may also mean the marked one it lacks when Ignore accents is on (a prefix or suffix hyphen counts as a mark here, `e-mail` keeps its own): `terug` is `terug` or `terug-`, `een` is `een` or `één`. When nothing is written so, the settings' leniency decides (hints dropped, the same hyphen let go). One match links it; several open the picker with a first section "The typed answer is" (`MixUpSheet` `typed`), and closing it unanswered leaves the `≈` pill under the answer card ("Which word?") to reopen it. The pill shows after any wrong first try, so a typed mix-up can also be picked by hand. Next with a mix-up standing misses both, as Forgot does in a recall; I was right takes back the links this step made (`linked`), not ones made earlier.
  - The other card joins the cards ahead as missed, deck cards outside the session included, at half the retry gap: it comes back before the current card with other cards between.
  - A card's sheet lists the words it was mixed up with, each opening its sheet and with a cross that unlinks both ends, and + Add opens the same search to link one by hand (nothing graded).
  - Linked cards chain into groups. Learning and review take a card's whole group in, each group right after its first card; learning takes in any card of the deck not learned in all games on, review any learned card it plays in the game. Past the group size, unlinked cards go first from the end, then the smallest groups (later ones among equals) until the rest fit; a lone group still too big keeps its first cards, the group's own before the ones taken in. Room left over goes to unlinked cards in order.
  - Back from the card right after a game page shows that page again, before the previous game or leaving.
  - A game orders its cards as if none were passed; passed ones go by unasked but keep their place, so Back walks every card that came before, passed ones included.
  - The first Back after an answer, and Back from a game page, go to the card really answered last; the passed cards in between are skipped by that step.
  - A session opens on the page of its game when the cards are met by pronouncing and on every Continue (not on an update reload).
  - Meeting cards by pronouncing shows the native side on top; its page says to remember, say aloud and compare with the recording.
  - Lesson history persists. Resume continues at the same card in the same state (answer revealed or not).
  - All randomness is deterministic per lesson seed.
- **Postpone a card.** A button sends the card back at the first-rung gap, like any card, unchecked; a missed card keeps its rung, so its next answer climbs from there. Back puts it back in its place and shows it. A hint at game start explains it. In the voice-recording game, the hint says comparing your voice is optional.
- **Interface.**
  - Bottom buttons stick to the bottom of the screen.
  - The keyboard stays open on input screens.
  - Popups block scrolling, and their buttons stay clear of the rounded screen corners.
  - Every dialog is a `BottomSheet`: its actions and inputs (search, Done, confirm) sit in the footer in thumb reach, the title with ✕ on top.
  - Safe areas: every screen edge keeps at least `1rem` or the inset, whichever is larger: `max(1rem, env(safe-area-inset-*))`, or `calc(env(...) + 1rem)`. `1rem` in from a side and up from the bottom clears a corner rounded to about 54px, and Android often reports an inset of 0. The frame (`<main>` in `app.vue`) owns it, so every page gets it; the sticky `.actions` bar takes the frame's bottom padding over (negative margin), not adds to it. Sheets pad their panel the same way. `app/assets/safe-area.spec.ts` fails on any smaller clearance. Button rows still fit at 320px: labels never wrap or spill (`min-w-0`, smaller text and square buttons below 360px).
  - Text reads at WCAG AA (4.5:1) in both themes against every background it sits on (card, shaded box): red and orange text use the -700 shade on light and the -400 one on dark; `Prompt.spec.ts` checks the exception line. White text sits on orange-700 (5.2:1), never -500/-600; `app/assets/contrast.spec.ts` checks every white-on-orange class list in the sources. Grey text is stone-500 at its lightest on light and stone-400 on dark, so every `text-stone-500` carries `dark:text-stone-400`, never light stone-400 or dark stone-500; on a stone-100 chip it is stone-600. `contrast.spec.ts` checks every grey class list against its own background or the page and card. `app/components/card-contrast.spec.ts` renders the prompt and answer of every card kind, both sides, right and wrong, and checks each text against the background it actually sits on, a chip inside a tinted card included; 20px semibold is not large text, so the answer word needs 4.5:1 too.
  - A group's settings open from the gear at the right of its start menu title, over the menu: closing them (✕, backdrop or back) shows the menu again.
  - The recall timer runs from the right edge across the full width.
  - App controls select no text, and a long press shows no system link preview.
- **Settings and data.**
  - Settings save automatically.
  - **Sentences and combinations** (`utils/kinds.ts`). Sentence: a phrase or sentence that only shows words in use (`op zaterdagavond`). Combination: one of a rule-built series (`dinsdagochtend`, `vierentwintig`, `om negen uur`); the first of a series stays and its note says the rule. Verb forms, fixed expressions, survival formulas, idioms and terms are never flagged.
    - Settings has a switch per kind (`settings.kinds`), on by default. Off, those cards leave the deck everywhere (`shownCards` in the store's `compose`); their progress stays and comes back when switched on, so a passed section offers Learn again for them.
    - A group's menu has a settings gear (`KindSheet.vue`), shown when the group holds a flagged card: per kind, As in settings / On / Off (`settings.groupKinds`). The nearest own switch up the tree wins. A group with its own gets the `own cards` badge; one whose subgroups disagree shows Mixed. A switch that would replace subgroups' own ones lists what each gets and asks first, then clears theirs.
    - Settings says how many groups keep their own per kind and offers to reset them.
  - An update installs only at a move: from card to card in a game, or to another page (`noteMove`, called by `noteStep`). Never in the middle of a card: the cursor may be in a field. The app reloads onto the same step without offering to continue. The reload mark (`utils/update-reload.ts`) holds the page it was set on; a lesson goes on silently only when it is that page, so an update reloading home still leaves the offer to continue. At a move it still waits while audio plays, while the user is typing or recording, while a game holds unsaved state (half a 5:5 pair) and while a DB write is pending (`holdUntilDone` in the kv/sessions/shows queues). UX must not suffer. `installAtMove` fires once: its own saves hold and release the update again, and re-firing looped forever (a vitest hang).
  - Import: a Lexilize export keeps its progress; a backup restores progress.
  - A backup holds everything stored: learning, every game's review schedule with its due times, games passed, today's review log, answer counts, settings, own cards and course edits.
  - **Reset by long press**, a sheet that asks twice before anything changes. Answer counts always stay.
    - Learn (in a section's menu): the section's words go back to new; learning, games passed and review schedules go.
    - A review game (in a section's menu, or the home review menu): that game's schedule of those words goes, so they are due now and their gaps start over. Learning stays.
    - The home Review button: the same for every review game at once.

- **Linked words.** A note's reference items (`от:`, `уменьш. от:`, `мн. ч. от:`, `вариант:`, `не путать с:`, `синоним:`, `родственное:` and their translations, a gender mark allowed before them) link each named word to its card: dotted sky underline, tappable (`app/utils/links.ts`, `NoteText.vue`). A word no card has stays text; a card never links to itself; among cards of one spelling the gloss picks the one. Every link shows on its target's sheet too: an origin label under «Words built on it», any other label (a plural, a form, a variant, a word not to confuse it with) under «Related words», less the cards the target's own note already links (`buildIndex` `related`, `CardSheet.vue`). So a mention of another card is always a labelled link, never a bare `eruitzien — выглядеть`: the word built on the base says `от:` and the base lists it by itself.
  - Every part a note or a breakdown names is a card, so every part links: `app/utils/part-links.spec.ts` checks it in every language. A chain spelled after its parent (`от: verkopen (…) = ver- (…) + kopen (…)`) splits at ` = ` too.
  - A tap opens a bottom sheet on that card (`CardSheet.vue`, `useCardSheet`): word with audio, transcription, every meaning (the one the link gave highlighted), note with its own links, example, learned or not, and the words built on it (cards whose `от:`/`уменьш. от:` names it) in deck order, each tagged with the meaning it builds on when the word has several (the link's meaning highlighted). Opened while an answer is secret, the sheet leaves the asked card out of those lists.
  - A shown answer card has a ? in its top right corner (`card-details`): it opens the sheet on the card itself. Not there while the answer is hidden.
  - **Learn again** (`card-sheet-relearn`, beside learned or not) is there while the word or a word built on it is learned: the word goes back to new (learning, games passed, review schedules; answer counts stay). With learned words built on it or formed from it, at any depth (`familyOfWord`: origin labels and form labels, followed down), it asks first: only this word, or with those N words («With N learned words from it»); the last choice comes first and highlighted (`settings.relearnDeep`), focus on it, Cancel last. With none, it applies at once.
  - Sheets stack. The device's back button closes the top one, as in focus-assistant (`app/utils/back.ts`: one history entry for all layers, a handler stack over it); the sheet's ‹ does the same, ✕ and the backdrop close all and remove the entry.
  - Going up a page (`‹`, To sections) uses `UpLink.vue`: back in history when the target is the entry right below, else a replace, so history never grows by going up and back on home never walks through earlier pages.
  - Home is the last stop: arriving on it from another page (a link, Back, `‹`) goes back to the app's first history entry and puts home there (`utils/home-first.ts`), so no earlier page is behind it. A hash menu opening on home is no arrival.
  - Back with nothing open on the app's first page asks `Leave Van start?` (`LeaveSheet.vue`; a guard entry over the first one in `app/utils/back.ts`). Leave goes back past the app; with nothing before it (an installed app), it tries to close, and else says the next back leaves. Stay, ✕ or another back keep the app, and the next back asks again. Back onto the first page from a page the router opened on it (its `forward` set: no guard above it yet) asks nothing; it clears `forward` and guards, so the next back asks.
  - While a sheet is open the answer clock stops.
  - The typed-letter diff (`TypedLetters.vue`, `diffLetters` in `utils/answer.ts`): right letters green; a wrong run struck through in a red box, then the letters it misses: `_` while the answer is hidden, the right letters, green and underlined, once it shows (`reveal`): `[naar]__ vakantie gaan`, `[v]_elicit[i]eren`. Never a wrong letter in place of a right one, which hides what was meant. An extra or wrong space is drawn as `␣`: a struck blank reads as a typed hyphen.
  - The sheet slides up and fades its backdrop in (200 ms), slides out on close (150 ms), as focus-assistant's `Dialog.vue`. A finger drags it down; let go past a quarter of its height it closes, else springs back. The body takes the gesture while scrolled. Header (word, audio, ✕, transcription) stays put; only the body scrolls.

2. Deploy:

- A spec whose order comes from a seed holding the date pins its day with `vi.useFakeTimers({ toFake: ['Date'], now })`: on some days a hard word jumps ahead by its odds, so an unpinned spec fails by the calendar.
- An unfinished review is kept in the `session` table (`review-left:<path>:<game>`, via `sessions` in `app/db/sessions.ts`) after each answer and picked up on the next visit at the same card; a finished one is dropped.
- Review starts with the hardest words of its game (misses over right answers, most first), then the order they were learned in; a card missed in the review's own game may jump ahead by its odds (`ordered` in `pickIndex`).
- A resumed session goes on counting steps from its history, so a miss keeps its comeback spacing across leaving and returning.
- A resumed session rebuilds from its history which card each step showed, so a miss's wait is still filled from all cards shown before; else it comes back early or one card fills the whole wait.
- A passed card going by does not count toward a miss's gap, nor as a card left to fill it.
- Backup is our own .json (store export plus unfinished sessions under `sessions`: `learn-resume:*`, `review-left:*`), shared via the share sheet where there is one, else downloaded, named `van-start-<UTC date>-<HHMM>-v<build version>.json`. Lexilize is import-only.

## Session scheduler (`app/utils/scheduler.ts` holds the rules; `Session.vue` applies them on its queue)

- Clock is shows, not seconds. Answers: plus, minus, guessed, postpone.
- Guessed: back to the first rung like a miss, but never counted as an error or toward accuracy.
- Ladder of gaps from 4 up to the session size N (group size from settings; review: its card count), x4 per rung, at least 4 rungs where N allows: 20 -> 4,7,12,20; 100 -> 4,12,34,100; 256 -> 4,16,64,256. N < 16 climbs by 4.
- Miss: back to the first rung. Plus: next rung; past the top the card is passed. Slow plus: like Guessed (back to the first rung, ungraded), but logged as a plus so its time stays in the sample. Slow = an outlier among the game's last 200 timed pluses, once there are 10: over `exp(median + 3 x 1.4826 x MAD)` of the log times, and at least 1.5x and 1 s over the median (`slowAfter` in `app/db/shows.ts`). A fixed 2x median ignored the spread: too lax for steady answers, too strict for wide ones. A new card right at once is passed. Slowness judges answers only: an intro card asks nothing, so it passes however long it was looked at (a slow intro once carried words like `het busje` unpassed, and every Continue reopened the intro).
- Postpone: back at the first-rung gap, the card's own rung kept, not logged as a show, never counted as an error or toward accuracy.
- Missed-card progress: a card on the ladder shows `ProgressPie` (ring plus sector filled to rung / `steps.length`) in the card's top-right corner, from the moment a miss shows its right answer (`rungShown`: empty ring), one rung up while a right answer is out; it needs `steps.length - rung` more right answers (fewer rungs in small decks: `ladder`, sized per game by the words it asks: those not passed in it when the session began); a slow one or a new miss restarts at rung 0.
- No fillers. When only misses still waiting their gap are left, the game lets them go unpassed (`stranded` in Session.vue) and emits `carried` for each: an unpassed card stays unlearned, so it opens the next group, whose games and the step between groups space it. learn.vue rates a carried card Hard and the done screen says `N hard words move to the next group`. A card put off is no miss (no `rung`) and still comes back. Putting off a card it was mixed up on (Later, also after Back) takes the mix-up back too: the words it was taken for are not missed, and the links that step made are undone. A saved `filler` flag from older sessions is ignored; such a card never emits `passed`.
- Known mark: every card with a stored score in the game or a miss this session carries the `FillerIcon` badge (head with a spark, `data-testid="known"`) in place of the ring, coloured by how well it is known (`utils/known-colour.ts`: oklch hue from red 25 to green 145, lightness and chroma fixed; formula below); a card new to the game has none. Once missed it shows the ring instead. Session reads stored misses per card and game from the `gameScores` prop (learn.vue passes `store.scores`). The ring shows only on a card missed and not yet through its ladder: empty after the miss, filling with each right answer, emptied by a new miss.
- Typing again: wrong tries before the answer is revealed count as the one miss; a wrong try after Reveal answer (or No idea) emits `miss` and counts one more, undone by Back.
- Typo claims: `I was right` shows once the answer is revealed over a typed try, unless that try was typed after the answer had been shown (`retried`). A claim on a later try (`again`) finishes the card but keeps the first try's miss.
- A saved session spot is taken only when every card id in its queue and history is in the group or the pool (`resumeFrom` returns false otherwise, and the game starts afresh): a stale id crashed the lesson to a blank page (`reading 'id'`).
- Deploy keeps old `_nuxt` chunks (`rsync --exclude _nuxt`): a page still on the previous version loads its lazy chunks after the deploy; deleting them gave a black screen (NUXT_E1005) on opening a lesson. No `skipWaiting`/`clientsClaim`: a new worker must not take over an open old page.
- Update on reload: the plugin checks for a new service worker at start and watches the registration itself (`takeOverAtMove`): a worker found waiting, or one that finishes installing later, gets `SKIP_WAITING` at the next move while nothing holds the update. Not through `$pwa`: the PWA module's plugin is `enforce: 'post'`, so in ours `$pwa` is still undefined, and the new worker sat waiting until every tab closed (several reloads). When one takes over (`controllerchange`, `reloadOnNewWorker`) the page reloads within that move (`MOVE_GRACE`), or at the next one, so one reload brings the new version. While the app is in view it also checks every minute and on coming back into view (`checkWhileOpen`): GitHub Pages serves `sw.js` with `max-age=600`, so a deploy can take ~10 min to reach a phone, and polling brings it without manual reloads. Every step in a game and every route change also checks (`noteStep`), at most once in 5 s. Repro with a real browser: `scripts/update-repro/` (`python3 -I serve.py <root> 8790` emulates Pages: `x` -> `x.html`, `max-age=600`; `node upd.mjs <root> <A> <B> reload|step` takes two `NUXT_APP_BASE_URL=/van-start/ pnpm build` outputs a minute apart, deploys B over a controlling A and logs the version and the registration's state).
- Recall time: table `recall:[word, game]`, median of the card's last five timed pluses, kept by the `recall_ms` event on show create/delete; read into memory by `loadTypical`, served by `recallMs`. Migration 002 fills it from older shows. A show's `ms` ends at the answer: the reveal (recall games), the pick (choice), the check (typing); reading the result before moving on is not timed, else a missed card read at length came back slow every time and circled without climbing. In the typing games a show's `ms` leaves out the typing: the typing is subtracted, so a long word is not timed as a slow recall. `utils/typing-pace.ts` learns the user's typical key gap (median of the last 200, localStorage `typing-gaps`, the answer being typed included from its third gap); a gap up to 4x typical (clamped 0.6-2.5 s: accents, long-press, fixes) is typing, a longer one is thinking of which one typical gap counts as typing. Gaps under 40 ms (paste, autocomplete) are not learned.
- Update toast: `announceUpdate` (pwa-update plugin) compares the build version with `seen-version` in localStorage and shows "Updated to <version> UTC" for 3 s.
- Jitter: gaps >= 8 get 0..floor(gap/4) extra, by the session seed.
- Pick: due ladder card -> new card while the pool is not full -> end when nothing is pending -> filler (a passed card not shown in the last 10 shows, max (errors+0.5)/(shows+1) x age; a miss puts it back on the ladder, no limit) -> earliest ladder card.
- Pool starts at 4, min 2, no max: every 10 answers accuracy > 85% -> +1, < 75% -> -1 (85% rule).
- The ladder applies to every game where an answer can be wrong, listening included.
- Back after an answer (right, wrong, postpone) undoes it fully; the user answers again.
- In `Session.vue`: a queue item carries `rung`, `missedAt` and `spacing`; `pickIndex` brings it back exactly when `spacing` shown cards passed. N is `retryGap` (learn: group size) or the stage's card count (review). Slow comes from the `isSlow` prop (`app/db/shows.ts`). Each answer and put-off is emitted as `show` (id, game, answer, ms, rung, source) and taken back by `unshow` on Back; pages log them with `sessionLog`.
- Not yet in `Session.vue`: the adaptive pool and fillers (cards come in the stage order); ladder state lives in the session's queue, not on a word x game relation.

## Storage (SurrealDB)

- Embedded SurrealDB, latest `surrealdb` / `@surrealdb/wasm` / `@surrealdb/wasm-native`, `surrealkv://` in a dedicated worker; `mem://` in tests.
- `app/db/connect.ts` `useDb()` opens the db and runs the idempotent `SCHEMA` (`app/db/schema.ts`); `resetDb()` gives tests a fresh `mem://` one.
- `app/db/kv.ts` `load`/`save` back `useStore`: progress -> `word`, gameScores -> `score`, passed -> `passed`, reviews -> `review` (id `[game, word]`), anything else -> `doc`. Each save is one transaction writing only changed rows. Each save still clones and diffs the whole store, so a batch goes in one save: a finished group is learned by `learn` (one write of progress, one of reviews), never word by word, which stalled a 100-card group.
- Unfinished sessions (`learn-resume*`, `review-left*`) live in the `session` table through the sync cache `sessions` (`app/db/sessions.ts`), loaded before mount.
- `app/plugins/00.db.client.ts` migrates, then loads sessions and typical times, before the app mounts.
- Show log per answer. The slow limit per game is computed in memory from its last 200 timed pluses (`refreshTypical`, after each logged show); `stats:<game>` (kept by an event on `show` insert) only lists the games for `loadTypical`.
- Migrations are numbered steps; `schema_version` in the DB (none = 0). On start every step above the current version runs in order, each in a transaction, idempotent, version written after each; a failed step stops and retries next start. The app does not start until done, only a progress bar shows. Steps load lazily (`() => import(...)`), so an up-to-date user downloads none.
- Step 1 copies the old IndexedDB store and localStorage sessions into SurrealDB. The old IndexedDB is kept until a later step cleans it, once the user confirms the move.
- Backup carries the show log and `schema_version`; an old backup goes through the same migration chain.

- The `left` counter counts shows still to come if every answer from now on is right, carried misses left out (`utils/shows-left.ts` plays the queue forward the way `pickIndex` and `stranded` take it), so each right answer takes exactly one off and only a miss makes it grow.
- Card colour (`knownColour`): green for a card never missed in the game; otherwise the share `right / (right + 4 x wrong)` moves the hue from red to green, since each miss wants 4 fixes. It colours both the known mark and the ring of a missed card.
- Putting a card off (`putOff`) keeps its rung as is: a card never missed comes back once, with no ring.


- **Deferred work.** Anything postponed during a pass goes into `.proof/todo.md`; a pass is done only when that file is empty.
